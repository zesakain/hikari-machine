# Editor Keyboard Input & Text Input Architecture

## 1. Overview & Architectural Role

The **Hikari Editor** is an interactive, native desktop editor embedded within the Hikari game engine. To ensure responsive developer workflows—including renaming assets, typing numerical parameters, searching hierarchies, entering directory names, and navigating panels via keyboard shortcuts—the editor relies on an end-to-end, zero-latency input pipeline from the host operating system (Wayland/X11 on Linux) down to Dear ImGui widgets.

Prior to this fix, the editor experienced a critical defect where mouse interaction functioned normally, but keyboard input and text editing were completely non-functional across all windows and modals.

---

## 2. Root Cause Analysis of the Input Failure

Tracing the pipeline revealed five distinct architectural defects that collectively broke keyboard interaction:

1. **Dear ImGui Event Forwarding Gap (`editor_engine.cpp`):**
   `EditorEngine::processInput(const platform::InputSnapshot& input)` previously only forwarded mouse events (`io.AddMousePosEvent`, `io.AddMouseButtonEvent`, `io.AddMouseWheelEvent`). Zero key events or character input streams were forwarded to Dear ImGui.
2. **SDL3 Text Input Suppression (`sdl_window.cpp`):**
   In SDL3, newly created windows have text input deactivated by default (`SDL_TextInputActive(window) == false`). Without invoking `SDL_StartTextInput(window)`, SDL3 suppresses all `SDL_EVENT_TEXT_INPUT` events on the OS event pump.
3. **Platform Event Pump Blindspot (`sdl_platform.cpp`):**
   `SdlPlatform::pollEvents()` processed mouse clicks, mouse movement, and `SDL_EVENT_KEY_DOWN`/`UP` only into a bitset of pressed keys, completely dropping `SDL_EVENT_TEXT_INPUT`, `SDL_EVENT_WINDOW_FOCUS_GAINED`, and `SDL_EVENT_WINDOW_FOCUS_LOST`.
4. **InputSnapshot Data Model Deficiency (`input_snapshot.h`):**
   `InputSnapshot` only contained a bitset `keys`, which was inadequate for:
   - Distinguishing key repeat events from initial down presses.
   - Tracking multiple rapid key events within a single simulation frame.
   - Carrying multi-byte UTF-8 character text streams generated by the OS IME/compositor.
   - Communicating window focus transitions.
5. **Dear ImGui Master Keyboard Navigation Flag Disabled (`editor_engine.cpp`):**
   `ImGuiIO::ConfigFlags` only enabled `ImGuiConfigFlags_DockingEnable`. The master keyboard navigation flag `ImGuiConfigFlags_NavEnableKeyboard` was omitted, causing programmatic focus requests (`ImGui::SetKeyboardFocusHere()`) to leave input widgets unfocused.

## 4. Subsystem Details

### 4.1 Window & Platform Text Input Control

`eng::platform::Window` defines clean, generic virtual methods for text input:
- `startTextInput()`: Calls `SDL_StartTextInput()`.
- `stopTextInput()`: Calls `SDL_StopTextInput()`.
- `isTextInputActive()`: Queries `SDL_TextInputActive()`.
- `setTextInputArea(int32_t x, int32_t y, int32_t w, int32_t h)`: Configures the on-screen IME candidate rectangle via `SDL_SetTextInputArea()`.

### 4.2 Zero-Allocation Hot-Path InputSnapshot

Per engine contract (AGENTS.md Section 6), zero dynamic memory allocations occur on the input polling path:
- `KeyEvent` records `{ KeyCode code, bool down, bool repeat }`.
- `keyEvents` buffer stores up to 32 discrete events per frame (`kMaxKeyEventsPerFrame = 32`).
- `textInput` stores up to 64 bytes of null-terminated UTF-8 character data per frame (`kMaxTextInputBytes = 64`).
- Compile-time invariant asserted: `static_assert(sizeof(InputSnapshot) <= 512)`.

### 4.3 Dear ImGui Platform Integration

- **Key Translation:** Complete 1-to-1 physical mapping `toImGuiKey(platform::KeyCode)` covering letters (A-Z), numbers (0-9), function keys (F1-F12), navigation (Arrows, Home, End, PageUp/Down), editing keys (Enter, Escape, Tab, Backspace, Delete, Space), and modifiers (Ctrl, Shift, Alt, Super).
- **Modifier Handling:** Evaluates state of left/right modifier pairs and emits `ImGuiMod_Ctrl`, `ImGuiMod_Shift`, `ImGuiMod_Alt`, and `ImGuiMod_Super`.
- **Text Streams:** Dispatches UTF-8 text directly via `io.AddInputCharactersUTF8()`, supporting multi-byte international characters and symbols.
- **Focus Routing:** Dispatches `io.AddFocusEvent(input.isWindowFocused)` upon focus gain/loss transitions.
- **Clipboard Integration:** Connects `io.GetClipboardTextFn` and `io.SetClipboardTextFn` to `SDL_GetClipboardText` and `SDL_SetClipboardText` with an in-memory fallback for headless execution.
- **IME Candiate Positioning:** Integrates `ImGuiPlatformIO::Platform_SetImeDataFn` with `SDL_SetTextInputArea` for correct IME placement on Linux Wayland/X11 desktops.

### 4.4 Modal Dialog & Panel Interactions

All modal dialogs in the Content Browser and Hierarchy panel follow standardized keyboard UX contracts:
- Initial appearance automatically focuses the input box via `ImGui::SetKeyboardFocusHere()`.
- `ImGuiInputTextFlags_EnterReturnsTrue` allows committing actions (such as creating or renaming folders) immediately upon pressing Enter.
- Pressing Escape cancels and closes the active modal dialog.

## 5. Verification & Testing

Automated tests in `tests/unit/editor/editor_test.cpp` verify:
1. **ASCII and Alphanumeric Input:** Typing "hikari", uppercase " ENGINE", and punctuation " 2026!".
2. **International Multi-byte UTF-8 Characters:** Ingesting UTF-8 characters (e.g. "Hikari-光").
3. **Editing & Backspace:** Accurate character deletion including multi-byte UTF-8 codepoint removal.
4. **Keyboard Shortcuts:**
   - Ctrl+A (Select All) + Backspace (Delete All).
   - Ctrl+C (Copy) + Backspace (Clear) + Ctrl+V (Paste).
   - Hierarchy Ctrl+D (Duplicate Selected Entity).
   - Hierarchy Delete (Delete Selected Entity).
5. **Window Focus Invalidation & Recovery:** Preserving widget state across window focus loss and regaining focus.
6. **Content Browser Operations:** Programmatic folder creation and renaming verified against the filesystem.
